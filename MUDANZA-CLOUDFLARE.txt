MUDAR PLEA5E A CLOUDFLARE PAGES
===============================

Por que nos mudamos
-------------------
Netlify paso a un sistema de creditos: cuando se agotan, la web sigue
online pero no se puede publicar nada hasta el mes siguiente. Cloudflare
Pages no tiene saldo que se agote: tiene topes diarios que se reinician
solos, y son tan altos que este negocio no los va a rozar.

Lo que hay que hacer, por orden
-------------------------------

1. CREAR EL PROYECTO
   dash.cloudflare.com -> Workers & Pages -> Create -> Pages ->
   Connect to Git -> elegir el repositorio.

   Ajustes de construccion:
     Framework preset .......  None
     Build command ..........  npm install
     Build output directory .  /            (la raiz, tal cual)

   El "npm install" no compila nada: solo baja la libreria de la IA para
   que la funcion la encuentre. Las paginas son HTML suelto.

2. EL ALMACEN DE PEDIDOS
   Sin esto el panel no tiene donde guardar nada.

   a) Workers & Pages -> KV -> Create namespace.
      Nombre: encargos-plea5e   (el nombre da igual)

   b) En el proyecto de Pages -> Settings -> Bindings ->
      Add -> KV namespace
        Variable name ....  ENCARGOS      <- ESTE nombre SI importa
        KV namespace .....  el que acabas de crear

   Si el nombre de la variable no es exactamente ENCARGOS, el panel
   dira que el almacen no esta conectado.

3. LAS VARIABLES
   Settings -> Variables and Secrets. Las mismas de siempre:

     PANEL_CLAVE .........  la contrasena del panel
     RESEND_API_KEY ......  la clave de Resend (el correo)
     CORREO_AVISO ........  a donde te llegan los avisos
     CORREO_DE ...........  onboarding@resend.dev
     ANTHROPIC_API_KEY ...  OPCIONAL. Sin ella los colores los elige la
                            tabla por oficio de lib/encargo.mjs, gratis.

   Marcalas como "Secret" salvo los dos correos.

4. COMPATIBILIDAD CON NODE
   Settings -> Runtime -> Compatibility flags -> anadir:  nodejs_compat
   Lo pide la libreria de Anthropic. Si no la usas, tampoco estorba.

5. PROBAR ANTES DE TOCAR EL DOMINIO
   Cloudflare te da una direccion tipo  plea5e.pages.dev . Comprueba ahi:
     /                          la web
     /taller/generador.html     el generador de placas
     /taller/pedidos.html       el panel, con la contrasena

   Si el panel entra y dice "Todavia no ha entrado ningun pedido", esta
   todo bien. Si dice otra cosa, el mensaje explica que falta.

6. EL DOMINIO, LO ULTIMO
   Custom domains -> Set up a domain -> plea5e.es
   Hasta este paso, plea5e.es sigue sirviendose desde Netlify y no se
   entera nadie. Si algo sale mal en los pasos 1 a 5, no ha pasado nada.

Que se queda en Netlify
-----------------------
Nada importante. El netlify.toml sigue en el repositorio para que
plea5e.es aguante en pie mientras dure la mudanza. El dia que el dominio
apunte a Cloudflare, se puede borrar ese archivo.

Donde esta cada cosa ahora
--------------------------
  functions/api/encargo.js    recibe el pedido, elige colores, guarda,
                              manda el correo
  functions/api/encargos.js   lo que lee y actualiza el panel
  lib/encargo.mjs             la logica que comparten los dos: validar,
                              montar el enlace del generador y la tabla
                              de colores por oficio
  _headers                    el "no me indexes" del taller
  taller/generador.html       el generador de placas
  taller/pedidos.html         el panel
  gen/                        el codigo fuente del generador
  fuente/                     la tipografia Montserrat y su licencia

Para rehacer el generador despues de tocar gen/plantilla.html:
  npm install && python3 gen/construye.py
